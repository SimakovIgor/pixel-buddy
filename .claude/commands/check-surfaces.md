# Проверка питомца на всех клиентах

Запускать после любой правки мода. Цель: питомец ведет себя одинаково везде, ничего не выбивается, процессор не
грузится. Отчет простыми словами: что проверено, что нет, что разошлось.

## 1. Автоматика, обязательно

- `sh tests/run.sh`: все тесты зеленые. Тесты `on terminal|desktop|vscode petting and a caught ball give the same
  love ...` гоняют одно и то же на трех клиентах и сверяют результат
- `node $(ls ~/.npm/_npx/*/node_modules/typescript/bin/tsc | head -1) -p pixel-buddy --noEmit`
- `claude plugin validate --strict pixel-buddy`
- новое поведение закрыто тестом через вход (`$.ui.mount`, `press`, `post`, `turn.start`) и проверено мутацией на
  копии в scratchpad: со сломанным кодом тест краснеет

## 2. Правило одной логики

Терминал рисует полосу клиентом `hooks/band-client.tsx`, приложение Claude так же, а VS Code и Cursor получают
готовые кадры из `hooks/register.tsx` (функции `editor*`, `planOf`, `settleFood`, `settleToy`). Решения о том, что
случилось, везде одни: `petByHand`, `ate`, `caught`, `feedByHand`, `grow`, `cherish`, `menuOf`, рисует везде
`paint` из `hooks/scene.ts`.

- новое действие пишется общей функцией и вызывается из обоих мест, копия под один клиент запрещена
- движение в редакторе повторяет `targetOf` из band-client: работа уводит в правый угол, покой это пауза 7-16 с и
  прогулка, еда и мяч уводят к себе. Скорости 0,007 и 0,016 клетки в мс, оглядывания, прыжки и замедление
  уставшего и голодного те же. Поменял в одном месте, поменяй в другом и проверь тестом

## 3. Вживую, на каждом клиенте

- терминал: сессия Claude Code в любой папке, мод из рабочей копии
- приложение Claude: вкладка Code
- VS Code: тестовый профиль, чтобы не трогать настройки Игоря:
  `code --user-data-dir /tmp/pbvs/vd --extensions-dir /tmp/pbvs/ve <папка>`. Короткие пути нужны из-за лимита длины
  сокета Electron. Окно может быть на другом рабочем столе: перед кликом проверять, что впереди `Code`, а клавиши
  без нужды не жать
- Cursor: проверяет Игорь, нужен его вход

Сценарии, на каждом клиенте одинаково:

|---|---|---|---|

| отправить сообщение | | | уходит в правый угол и думает с точками, пока Claude работает |
| дождаться ответа | | | печенье падает в стороне, питомец идет и ест, растут опыт и сытость |

## 4. Плавность и процессор в VS Code

VS Code сам проигрывает анимацию внутри картинки, но после любой задержки кадра больше 100 мс замораживает ее на
5 минут. Поэтому кадры считает мод: каждая картинка несет 600 мс кадров вперед с шагом 50 мс, перерисовка не чаще
10 раз в секунду и только когда кадр сменился.

- лог расширения: `/tmp/pbvs/vd/logs/*/window1/exthost/Anthropic.claude-code/Claude VSCode.log`
- ровность кадров, интервалы между перерисовками:
  `grep "BENCH ui_render key=above-prompt#0 rid=[^ ]* C0=" "<лог>" | tail -200 | sed -E 's/.*C0=([0-9]+).*/\1/' | awk 'NR>1{print $1-p}{p=$1}' | sort -n | awk '{a[NR]=$1}END{print "p50",a[int(NR/2)],"p90",a[int(NR*0.9)],"max",a[NR]}'`.
  Норма: p50 до 60 мс, p90 до 120 мс
- процессор процесса claude этой сессии: `top -l 3 -s 2 -stats pid,cpu -pid <pid>`. Норма в покое до 5%,
  расширение пишет отладочный лог, без него меньше
- в картинке не должно быть бесконечной анимации (`infinite`): ее заморозит VS Code
